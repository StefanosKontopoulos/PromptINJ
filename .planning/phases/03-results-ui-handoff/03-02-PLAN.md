- Color direction: dark background preferred (e.g., near-black `#0E1117` with `#1A1D23` sidebar), OR clean light with blue-grey accents (e.g., `#F0F4F8` background, `#1E3A5F` headings). Provide BOTH options so Claude Design can choose.

SECTION 5 — Section-by-section layout description
Walk through the app top to bottom as a designer sees it:
1. **Page header area** — Title + caption centered at top. Should feel like a tool name, not a brand headline.
2. **Introduction text** — One paragraph, muted color, not competing with the upload zone.
3. **Divider** — Thin separator line.
4. **File upload zone** — Primary interactive element. Should be the visual focus of the page when no files are uploaded.
5. **Results area** — Appears below upload zone after scanning. Each file gets its own result block: banner (success/error/warning) + optional expander list. Visual separation between files when multiple are scanned.
6. **Finding expander** — When expanded: shows method label in header, extracted text in a code block inside. Should look like a forensics report, not a UI widget.
7. **Sidebar** — Persistent across scans. Lists filename + badge for each scan (✅ Safe / 🚨 N findings / ⚠ Error). Newest entry at top. Divider between entries. Empty state shows muted caption "No files scanned yet."
8. **Empty state (no files uploaded)** — Centered muted text below upload zone: "No files uploaded yet."

SECTION 6 — What NOT to change
- Do not rename or restructure any Python variables or Streamlit calls — the CSS selectors must match existing Streamlit-generated test IDs.
- Do not add new Streamlit components; only style existing ones.
- Do not change the semantic meaning of st.success / st.error / st.warning — their color should remain clearly green/red/yellow respectively.
- Do not add animations or transitions — this is a functional tool, not a marketing page.
