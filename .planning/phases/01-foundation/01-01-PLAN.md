# Plan 01-01: Project Scaffold

**Phase:** 1 — Foundation
**Wave:** 1
**Goal:** Create `app.py` skeleton with Streamlit multi-file uploader, 10 MB size validation, and `requirements.txt`. Detection is stubbed — app runs and layout is fully functional.

## Objective

Scaffold the complete app entry point with all file-upload functionality working end-to-end. Detection calls will return a stub result (`{"status": "pending", "findings": []}`). This plan establishes the project structure and verifies the dev environment is correctly wired before any detection logic is written.

## Context

- Tech stack: Python 3.10+, Streamlit ≥ 1.32, PyMuPDF ≥ 1.23, python-docx ≥ 1.1
- All processing is local — no external API calls
- Single `app.py` file — no submodules in Phase 1
- Session state (`st.session_state`) initialized here; used by Phase 3 for scan history
- UI visual design is deferred to Claude Design (Phase 3); Phase 1 layout is functional only

    2. **Page config** — `st.set_page_config(page_title="PromptINJ", page_icon="🔍", layout="centered")`

    3. **Session state init** — at startup, initialise `st.session_state.scan_history` as an empty list `[]` if the key does not already exist.

    4. **Title + subtitle** — `st.title("PromptINJ")` and `st.caption("Trojan Prompt / Honeypot Detector")`

       ```python
       uploaded_files = st.file_uploader(
           "Upload assignment files to scan for hidden instructions",
           type=["pdf", "docx", "txt"],
           accept_multiple_files=True,
       )
       ```

    6. **Size validation loop** — for each file in `uploaded_files`:
       - Compute size: `size_mb = len(file.getvalue()) / (1024 * 1024)`
       - If `size_mb > 10`: emit `st.warning(f"⚠ {file.name} exceeds 10 MB ({size_mb:.1f} MB). Large files may be slow to process.")` and `continue` (skip detection for now).

    7. **Stub scan call** — for each file that passes the size check:
       - Call `scan_file(file)` (defined below)
       - Display stub result: `st.info(f"📄 {file.name} — detection not yet implemented (Phase 2)")`

    8. **`scan_file(file)` stub function** —
       ```python
       def scan_file(uploaded_file):
           """Stub. Returns pending result dict. Replaced in Phase 2."""
           return {"status": "pending", "filename": uploaded_file.name, "findings": []}
       ```

## threat_model

```yaml
threats:
  - id: T1
    description: User uploads a maliciously crafted file that exhausts memory during .getvalue()
    severity: low
    mitigation: Size check uses len(file.getvalue()) — worst case is one oversized file in memory; Streamlit's 200 MB upload limit provides an outer bound
  - id: T2
    description: Unsupported file type bypasses the uploader's type filter
    severity: low
    mitigation: Streamlit's type= parameter enforces client-side filtering; server-side type check added in Phase 2
```
